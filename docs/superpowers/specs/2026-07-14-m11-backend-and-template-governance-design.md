# M11 前后端分离与 Drain3 模板治理设计

## 目标

在 M11 Drain Template Quality Center 中补充两项能力：前端可连接任意 LOGRISK 后端；操作员可治理 Drain3 模板，并安全执行需要二次确认的生产覆盖与回滚。系统继续保留原始模板标识、批准规则和 Lineage 兼容性。

## 后端地址与跨域

前端 API 地址按以下优先级解析：浏览器 `localStorage` 覆盖值、`frontend/config.js` 的部署默认值、当前页面同源地址。系统设置页提供地址编辑、连通性测试、保存和恢复默认。地址只接受 `http://` 或 `https://`，去除末尾斜杠后统一交给 API 客户端拼接路径。

Dashboard 增加轻量健康检查、`OPTIONS` 预检和 CORS 响应。允许来源由环境变量配置；默认仅支持同源及回环地址，避免无条件开放跨域。前端部署到其他域名时，运维人员显式配置允许来源。

## 模板治理模型

不直接改写 Drain3 聚类树或持久化快照。系统增加版本化模板覆盖层：

- 原始 `template_hash`、原始模板和实例 Fingerprint 永久保留；
- 有效模板可被编辑、忽略、恢复、合并或软删除；
- 合并记录目标模板，不伪造新的原始 Hash；
- 后续模板展示和质量评测读取有效模板，原始值仍用于审计及旧规则匹配；
- 直接治理操作必须携带确认标记和预期版本，防止误操作及并发覆盖。

状态保存到 `state/drain_quality/template_overrides.json` 和追加式 `template_events.jsonl`。每个事件包含 Schema 版本、操作人、时间、变更前后值和版本号。写入使用临时文件加 `os.replace()`。回滚通过追加补偿事件恢复指定历史版本，不删除审计记录。

## 页面与 API

“评测中心 → 模板质量”包含概览、标注工作台、可疑模板、配置对比、模板管理和发布管理。模板管理支持筛选组件、状态和风险关联，查看原始/有效模板差异，并执行编辑、忽略、恢复、合并、软删除和版本回滚。

API 增加模板列表、详情、变更、历史与回滚接口。错误响应明确区分非法地址、连接失败、版本冲突、模板不存在和缺少二次确认。Profile 发布仍需人工确认，且不会自动修改生产 Drain3 配置。

## 安全与验证

页面只渲染文本节点，不注入原始 HTML。模板目录只保存 Drain3 脱敏模板，不保存原始日志。测试覆盖地址优先级、跨域预检、模板操作、乐观并发、软删除、审计回放、回滚、API 契约及前端交互契约，并执行项目全量 pytest、compileall 和 Shell 校验。
